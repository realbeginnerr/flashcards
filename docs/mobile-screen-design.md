## 1. 설계 기준과 미정 사항

### 확정된 기준

- 누구나 로그인 없이 학습하는 독립 서비스다. 운영자만 Google 계정으로 로그인한다.
- 용어 239개와 승인된 다섯 분야 분류를 사용한다. 복수 분야인 카드도 한 회차에 한 번만 나타나고 이해도를 공유한다.
- 카드 뒤집기, 이해도 표시, 모른다고 표시한 카드 복습이 핵심이다.
- 비회원도 모든 카드를 학습할 수 있으나 진행 기록은 페이지를 닫거나 새로고침하면 사라진다. 회원 기록만 로그인 계정의 Firestore 저장소에 저장한다.
- 모바일을 먼저 설계하고 PC에서도 같은 기능을 제공한다.
- 기존 녹색 계열, Pretendard/Inter, 각진 버튼 스타일을 재사용한다.
- 객관식·주관식, 간격 반복, 기록 내보내기·가져오기는 이후 검토 범위다.

### 확정된 선택과 기본 설계

| 항목 | 설계 상태 |
| --- | --- |
| 서비스명 | 붕억빵 — 사용자 확정 |
| 한 회차 카드 수 | 10장 — 사용자 확정. 마지막 묶음은 남은 수만 표시. N은 해당 회차의 실제 수량 |
| 카드 앞면 영문 | 한글명과 영문·약어 함께 표시 — 사용자 확정. 없는 영문은 생략하고 같은 표기는 한 번만 표시 |
| 이해도 | 기존 PRD의 ‘알아요 / 몰라요’ 2단계 제안을 적용 |
| 분야 선택 | 전체 또는 하나의 분야를 선택하는 단일 선택 제안 |

한 회차 10장을 기준으로 설계한다. 다음 묶음은 아직 학습하지 않은 카드부터 이어가고 마지막 묶음은 남은 수만 표시한다. 묶음 이어보기·순환은 아래 기본 설계이며, 사용자 확정 사항인 이름·수량·앞면 표시와 구분한다.

## 2. 전체 화면 흐름

```text
시작 화면
 ├─ 분야 선택 → 학습 시작 → 카드 앞면
 │                           ↓ 설명 보기
 │                         카드 뒷면
 │                           ↓ 알아요 / 몰라요
 │                         다음 카드 앞면 → 회차 완료
 │                                           ├─ 모르는 용어 복습
 │                                           └─ 처음으로
 ├─ 모르는 용어 복습 → 몰라요 카드만 같은 방식으로 학습
 └─ 관리자 → Google 로그인 → 용어 관리 목록
                              ├─ 용어 추가
                              └─ 용어 수정 → 삭제 확인
```

공개 회원가입은 제공하지 않으며, 승인된 일반 사용자의 로그인·마이페이지 진입을 헤더에 제공한다. 일반 학습과 복습은 같은 카드 화면을 재사용한다.

## 3. 시작 화면

### 배치 도식

```text
┌──────────────────────────┐
│ 붕억빵                   │
│                          │
│ 낯선 용어를, 익숙하게      │
│ 뜻을 떠올리고 확인해보세요.│
│                          │
│ 학습 분야                 │
│ ● 전체          239개     │
│ ○ UX/UI 디자인            │
│ ○ 개발                   │
│ ○ AI 툴                  │
│ ○ 마케팅                 │
│                          │
│ [       학습 시작       ] │
│ [ 모르는 용어 복습 · M개 ]│
│                          │
│ 로그인하면 학습 기록을    │
│ 저장할 수 있어요.         │
│                  관리자  │
└──────────────────────────┘
```

### 표시와 동작

- 큰 사진·장식보다 분야 선택과 시작 버튼을 우선한다.
- 분야는 가로 스크롤 칩 대신 세로 선택 목록으로 배치한다. 긴 ‘UX/UI 디자인’도 줄어들거나 잘리지 않게 한다.
- 전체 수는 중복 제거한 239개, 분야 수는 해당 분야에 속한 카드 수다. 분야별 수를 더해 전체 수로 표시하지 않는다.
- 현재 데이터 기준 분야 수: UX/UI 디자인 145개, 피그마 46개, 개발 141개, AI 툴 12개, 마케팅 33개. 실제 화면은 콘텐츠 조회 결과로 계산한다.
- ‘모르는 용어 복습’의 M은 현재 유효한 전체 카드 중 ‘몰라요’인 수다. 선택 분야와 독립된 전체 복습임을 문구로 구분한다.
- 복습 대상이 0개여도 버튼을 숨기지 않는다. 누르면 ‘모르는 용어가 아직 없어요’와 ‘학습 시작하기’를 제공한다.
- 일반 사용자는 관리자 로그인 없이 이용한다. 관리자 진입은 하단의 작은 텍스트 링크로 둔다.
- 기록 저장 범위는 짧게 안내하고, 상세 설명은 필요한 경우 펼쳐 읽게 한다.

## 4. 학습 카드 앞면과 뒷면

### 앞면

```text
┌──────────────────────────┐
│ 종료               1 / N │
│ ─── 진행 표시 ─────────── │
│ UX/UI 디자인              │
│                          │
│                          │
│       카드 소팅          │
│       Card sorting       │
│                          │
│ 뜻을 먼저 떠올려보세요.    │
│                          │
│ [       설명 보기      ] │
└──────────────────────────┘
```

- 용어와 분야가 먼저 보이며, 한글명 아래 영문·약어를 보조 크기로 함께 표시한다. 일반적인 회차는 1 / 10, 마지막 묶음은 1 / 실제 남은 수로 표시한다.
- 약어·영문 자체가 용어인 Git·n8n·PaaS 등은 원문 식별자를 그대로 표시한다. 한글명을 임의로 만들어 대체하지 않으며 동일한 표기가 두 줄 반복되지 않게 한다.
- 진행 표시는 ‘이 회차에서 몇 번째인가’를 나타낸다. 점수·지식 수준·암기율로 표현하지 않는다.
- 설명 보기 전에는 이해도 버튼을 표시하지 않는다.
- 카드 전체를 터치해야만 넘어가는 방식 대신 명시적인 ‘설명 보기’ 버튼을 제공한다. 스와이프는 필수 동작이 아니다.

### 뒷면

```text
┌──────────────────────────┐
│ 종료               1 / N │
│ UX/UI 디자인              │
│ 카드 소팅                 │
│                          │
│ 뜻                       │
│ 사용자에게 카드를 주고    │
│ 직접 분류하도록 하는…     │
│                          │
│ 예시                     │
│ 운동화·등산화·샌들 카드를 │
│ 사용자가 분류하도록 한다. │
│                          │
│ [용어 보기]              │
│                          │
│ [ 몰라요 ]   [ 알아요 ]  │
└──────────────────────────┘
```

도식의 문장은 배치 설명용 축약이다. 실제 카드에는 승인된 정의·예시 전체를 표시하고 말줄임으로 숨기지 않는다.

### 내용과 버튼 배치

- 카드 뒤집기는 용어 중심 화면에서 설명 중심 화면으로 전환한다. 복잡한 3D 회전은 필수로 두지 않는다.
- 읽는 순서는 용어 → 정의 → 예시 → 필요 시 주의·출처다.
- 예시가 없는 카드는 빈 제목을 만들지 않는다. Mermaid 코드·스킬 폴더 구조 등은 줄바꿈을 유지한다.
- 긴 내용은 페이지 전체에서 세로 스크롤한다. 작은 카드 안에 별도 세로 스크롤을 만들지 않는다.
- 이해도 버튼은 하단의 동일한 크기 두 칸으로 배치한다. 기본 제안은 왼쪽 ‘몰라요’, 오른쪽 ‘알아요’다.
- 긴 내용을 읽는 중에도 접근할 수 있도록 하단 행동 영역을 sticky로 제안한다. 내용 아래에 충분한 공간을 확보하고 모바일 안전 영역을 반영해 마지막 문장을 가리지 않게 한다.
- 화면이 낮거나 글자를 크게 키웠을 때 sticky 영역이 본문을 과도하게 가리면 문서 흐름 안으로 되돌린다.
- ‘몰라요’는 오류가 아니므로 빨간 오류 버튼으로 표현하지 않는다. 두 평가는 동등하게 읽히되 주요 강조색은 필요한 행동에만 사용한다.

### 상태 변화

1. 평가를 누르면 해당 카드 ID에 이해도를 저장하고 다음 카드의 앞면으로 이동한다.
2. 중복 터치가 다음 카드까지 평가하지 않도록 현재 카드 ID와 처리 상태를 확인한다.
3. 종료하면 이미 평가한 기록은 유지한다. 현재 평가하지 않은 카드는 이전 상태를 유지한다.
4. 마지막 카드 평가가 끝나면 완료 화면으로 이동한다.
5. 같은 회차 중 삭제된 카드는 건너뛰고 남은 수를 맞춘다. 조회 실패를 카드 삭제로 오인하지 않는다.

## 5. 완료 화면과 모르는 용어 복습

### 완료 화면

```text
┌──────────────────────────┐
│ 붕억빵                   │
│                          │
│ 이번 학습을 마쳤어요.     │
│                          │
│ 확인한 카드      N개      │
│ 알아요           A개      │
│ 몰라요           B개      │
│                          │
│ [이번에 모른 용어 복습]   │
│ [       처음으로       ] │
└──────────────────────────┘
```

- 위 수는 이번 회차의 마지막 자기 평가다. A+B=N이며, 실제 암기 성과나 정확도로 표현하지 않는다.
- 완료 화면의 복습은 ‘이번 회차에서 몰라요인 카드’를 대상으로 한다. 시작 화면의 복습은 ‘계정에 저장된 전체 몰라요 카드’를 대상으로 한다.
- 이번 회차의 몰라요가 0개이면 복습 버튼 대신 ‘이번에 모른다고 표시한 용어가 없어요’를 표시한다.
- 남은 카드가 있으면 ‘다음 10장 학습’을 제공한다. 마지막에 9장 남았다면 ‘남은 9장 학습’으로 표시한다. 선택 범위를 한 바퀴 끝내면 ‘처음부터 다시 학습’을 제공하며 이해도 기록은 유지한다.
- 일반 학습의 완료 묶음은 분야별 카드 ID로 계정 저장소에 저장한다. 미완료 묶음의 정확한 위치 복원은 필수가 아니며, 재진입 시 같은 묶음을 처음부터 시작할 수 있다.
- 복습은 시작 시 고정한 대상 목록을 최대 10장씩 이어가고, 같은 흐름에서 이미 본 카드를 다음 묶음에 반복 삽입하지 않는다. 최신 몰라요 재복습은 전체 대상 순회 후 별도로 시작한다.

### 복습 화면

- 상단에 ‘모르는 용어 복습’이라고 표시하고, 일반 학습과 동일한 앞뒷면을 사용한다.
- 복습 시작 시 대상 ID를 고정한다. 알아요로 변경해도 같은 회차의 카드 위치나 총수가 중간에 흔들리지 않게 한다.
- 이번 복습이 끝난 뒤 다음 복습 대상은 최신 ‘몰라요’ 상태로 다시 계산한다.
- ‘몰라요’를 고른 카드를 즉시 같은 회차에 반복 삽입하지 않는다.

## 6. 관리자 화면

### 로그인

- 제목 ‘관리자 로그인’, ‘Google로 로그인’, ‘학습으로 돌아가기’를 제공한다.
- 로그인 중 중복 실행을 막는다. 사용자가 취소하면 일반 실패 메시지로 겁주지 않고 다시 시도할 수 있게 한다.
- Google 로그인 성공 후 운영자 권한을 별도로 확인한다. 다른 Google 계정은 관리 기능을 사용할 수 없다.
- 허용할 계정 정보는 실제 인증을 연결할 때 확인한다. 화면 설계 단계에서는 이메일이나 비밀키를 받을 필요가 없다.

### 용어 관리 목록

```text
┌──────────────────────────┐
│ 용어 관리        로그아웃 │
│ [용어명 검색           ] │
│ [      용어 추가       ] │
│                          │
│ 카드 소팅                │
│ UX/UI 디자인       수정  │
│ ──────────────────────── │
│ Git                      │
│ 개발               수정  │
└──────────────────────────┘
```

- 모바일에서는 가로로 긴 관리 표보다 세로 목록을 사용한다.
- 용어명·분야와 수정 행동을 표시한다. 긴 정의를 목록에 모두 반복하지 않는다.
- 삭제는 편집 화면에서 제공해 목록 탐색 중 실수로 누를 가능성을 줄인다.
- 검색 결과 없음과 데이터 조회 실패를 구분한다. 조회 실패에는 재시도를 제공한다.

### 용어 추가·수정 공통 폼

입력 순서: 용어명(필수) → 영문·약어(선택) → 분야(하나 이상 필수, 체크박스) → 정의(필수) → 추가 설명·예시·참고 출처(선택).

- 분야는 복수 선택이다. 선택한 분야가 없는 상태는 저장 시 해당 그룹 아래에 안내한다.
- 긴 정의·코드·폴더 구조를 입력할 수 있는 여러 줄 입력란을 제공한다.
- 아래에 ‘저장 / 취소’를 두고, 수정 화면에만 ‘용어 삭제’를 별도 배치한다.
- 삭제 확인에는 실제 용어명을 표시한다. 취소하면 아무것도 변경하지 않는다.
- 저장 실패·권한 만료 시 입력을 지우지 않는다. 재인증 또는 재시도 후 이어갈 수 있게 한다.
- 변경한 내용이 있을 때 폼을 나가려 하면 버릴지 확인한다.
- 등록·수정은 같은 폼을 재사용한다. 관리자 로그아웃과 일반 학습 기록은 별개다.

## 7. 공통 디자인과 상태

### 디자인 적용

| 역할 | 설계 기준 |
| --- | --- |
| 주요 색상 | 기존 #255A46 |
| 기본 표면 | 흰색, 보조 표면 #F6F5F1 |
| 한글·제목 | Pretendard 계열 |
| 독립 영문·수치 | Inter 계열. 문장 안에서는 문장 언어 스타일 우선 |
| 버튼 | 기존 각진 스타일. 한 행 버튼의 높이 일치 |
| 모바일 배치 | 한 열. 좌우 여백 16px를 시작값으로 검토 |
| 주요 터치 영역 | 높이 48px를 프로젝트 제안값으로 검토. 작은 아이콘만을 조작 대상으로 만들지 않음 |
| 본문 | 16px·충분한 행간을 시작값으로 검토. 내용에 따라 높이 증가 |
| 학습 영역 폭 | PC에서도 읽기 좋은 단일 카드 폭을 유지. 구체 최대 폭은 화면 시안에서 확정 |

크기·간격은 프로젝트 제안이며 기존 디자인 시스템의 공통 규칙과 실제 모바일 배치를 함께 확인한다. 레시피의 메뉴·사진·영양 수치·목록 열 수는 적용하지 않는다.

### 주요 상태와 문구

| 상태 | 안내와 행동 |
| --- | --- |
| 콘텐츠 로딩 | ‘용어를 불러오는 중이에요.’와 로딩 표시 |
| 콘텐츠 조회 실패 | ‘용어를 불러오지 못했어요.’와 ‘다시 시도’ |
| 선택 분야 0개 | ‘이 분야에 등록된 용어가 없어요.’와 분야 변경 |
| 복습 대상 0개 | ‘모르는 용어가 아직 없어요.’와 ‘학습 시작하기’ |
| 기록 저장 실패 | ‘학습 기록을 저장소에 저장하지 못했어요. 다시 시도해주세요.’ |
| 관리자 권한 없음 | ‘이 계정에는 관리 권한이 없어요.’와 계정 변경·학습으로 이동 |
| 용어 저장 실패 | 관련 입력과 초안을 유지하고 저장 재시도 |

로컬 기록을 읽지 못한 상태를 ‘복습 0개’나 정상 저장으로 표시하지 않는다. 초기에는 임의 숫자를 넣지 않고, 실제 준비된 데이터만 표시한다.

### 접근성과 조작

- 버튼·링크는 이름을 명확히 하고 키보드 조작과 보이는 포커스를 제공한다.
- 색상만으로 분야 선택·이해도·오류를 표현하지 않는다.
- 숨긴 카드 면의 내용이 보조기기에 중복 전달되지 않도록 한다.
- 앞뒷면 전환과 다음 카드 이동 시 제목·현재 상태를 이해할 수 있도록 포커스와 안내를 설계한다.
- 뒤집기 애니메이션 없이도 사용 가능해야 하며 움직임 감소 설정을 존중한다.
- 문장·코드·긴 영문을 축소해 끼워 넣지 않는다. 코드 블록의 필요한 가로 스크롤은 페이지 전체 가로 넘침과 분리한다.

<a id="screen-8"></a>

## 8. 다음 구현 단계와 확인 기준

1. 확정된 붕억빵·10장·한글/영문 병기를 시안에 적용한다. 다음 묶음·마지막 묶음·전체 순환 동작을 함께 확인한다.
2. 앞면·뒷면·복습·완료를 실제 승인 콘텐츠로 확인하는 모바일 시안을 만든다.
3. 시작→설명 보기→이해도 선택→완료→복습 흐름을 연결한다.
4. 기록 저장과 관리자 인증·용어 관리를 연결한다. 시안에서 관리 데이터 저장이 구현됐다고 표시하지 않는다.
5. 작은 폭·낮은 화면·글자 확대·긴 정의·긴 코드·빈 상태·실패 상태를 확인한다.

검증할 핵심은 버튼이 눌리는가뿐 아니라, 사용자가 용어를 읽고 다음 행동을 이해할 수 있는가다. 현재 문서는 설계이며 실제 브라우저 검증·개발·배포 완료를 뜻하지 않는다.
