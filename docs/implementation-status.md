## 구현 기능

- 239개 용어, UX/UI 디자인·피그마·개발·AI 툴·마케팅 다섯 분야의 단일 분야 선택·복수 분야 소속. 피그마 분야는 관련 기존 용어 46개를 선별했다.
- 한글·영문 앞면, 설명 뒤집기, 알아요·몰라요 평가.
- 회차당 최대 10장, 마지막 남은 묶음, 다음 묶음, 처음부터 다시 학습.
- 비회원은 저장 없이 모든 카드를 학습할 수 있고, 회원만 계정별 Firestore 경로에 이해도와 분야별 완료 묶음을 저장.
- 전체 몰라요 및 이번 회차 몰라요 복습. 삭제된 ID는 현재 목록에서 제외.
- 기록 손상·저장 실패·조회 실패·빈 상태 안내.
- 관리자 Google 로그인 연결, 용어 목록·검색·등록·수정·삭제, 입력 검증, 수정 충돌 감지.
- 계정 삭제 요청은 Firestore에 저장하며, 무료 Google Apps Script가 매일 오전 9시와 오후 9시 근처에 미처리 요청을 관리자 이메일로 알리도록 구현 파일과 설정 절차를 제공한다. Apps Script 프로젝트 생성·권한 승인은 최초 1회 수동 설정이 필요하다.
- 관리자 폼에서 참고 출처와 긴 설명·코드·폴더 구조 입력 지원.

## 검증 결과와 한계

### 2026-11-23 전역 내비게이션 통일

- step 페이지의 별도 헤더를 제거하고 홈 헤더 HTML을 빌드에서 재사용한다. 스타일은 `src/header.css`, 검색과 모바일 펼침 동작은 `src/header.js`로 공통 관리한다. step 페이지의 초기 용어 조회는 수행하지 않고 검색 시에만 불러온다.
- `tests/header.test.mjs`를 기본 테스트 명령에 포함했다. 홈·step 페이지의 헤더 구조·목적지·계산된 스타일, PC 80px·모바일 60px 높이, 320/375/760px의 한 줄 유지와 검색 필드 펼침, step 페이지에서의 검색을 검증한다.
- Node.js 22에서 전체 테스트 71개와 정적 빌드 통과. 실제 브라우저 시각 검수와 운영 배포는 별도이며 이번 수정에서 수행하지 않았다.

### 2026-11-23 홈 초기 로딩 제거

- 후속 변경: 홈의 학습 진입은 `#/study`를 새 탭으로 여는 일반 링크로 전환했다. 학습 데이터 로딩·오류·재시도는 새 탭에서 처리하며, 원래 홈 탭은 그대로 유지한다. 관련 DOM 테스트와 전체 테스트 67개, 정적 빌드를 확인했다.

- 홈 최초 진입·새로고침은 가이드 카드를 바로 렌더링하고 용어·인증·학습 기록 조회를 시작하지 않는다. 초기 HTML의 용어 로딩 문구도 제거했다.
- 용어 목록은 검색어 입력 시, 사용자 학습 기록은 학습 시작·계정 진입 시 불러온다. 진행 중인 목록 요청은 공유하고, 홈을 유지한 채 학습 버튼 근처에 로딩·오류를 표시한다.
- 신규 테스트에서 홈의 외부 데이터 요청 0건, 첫 학습 시작과 저장 기록 복원, 요청 중복 방지, 실패 재시도, 검색의 목록 단독 조회, 학습 로딩 중 홈 이동 시 자동 시작 방지를 확인했다.
- Node.js 22.23.5에서 전체 테스트 67개와 정적 빌드 통과. 실제 브라우저의 초 단위 성능 측정과 운영 배포는 진행하지 않았다.

### 2026-11-23 배포 실패 진단·수정

- 대상: GitHub Actions 실행 `45017257749`, 커밋 `50f44c1`. `Run tests`의 타이머 화면 테스트 1개 실패로 이후 빌드·배포 단계가 실행되지 않았다.
- 로그에서 초기 표시 기대값 `0 / 10초`와 실제값 `1 / 10초`의 불일치를 확인했다. 테스트가 10초 제한을 30ms로 압축하고 실제 시계에 의존하여, 실행 속도에 따라 검사 전에 시간이 진행되는 경쟁 조건이 있었다.
- 두 타이머 테스트의 시계와 interval 콜백을 테스트에서 직접 제어하도록 수정했다. 실제 10초 설정을 그대로 사용해 0초, 1초, 만료 직전, 정확히 10초의 자동 뒤집기·타이머 해제와 수동 뒤집기 후 시간 진행을 검증한다. 서비스 코드는 이 수정으로 변경하지 않았다.
- Node.js 22.23.5에서 현재 전체 테스트 63개 통과, 정적 빌드 통과. 이번 수정으로 Firestore 규칙은 변경하지 않았으며 권한 에뮬레이터는 재실행하지 않았다.
- 수정은 로컬 작업본에 반영했다. 커밋·푸시·GitHub Actions 재배포는 아직 수행하지 않았다. 아래 표의 이전 배포 성공 기록과 이번 실패·수정 검증은 구분한다.

## 로컬 실행

프로젝트 폴더 `D:\flashcards`에서 다음을 실행한다.

```powershell
npm run dev
```

주소: `http://localhost:5174/`. 기존 레시피의 5173 포트와 분리했다. 사용 중인 포트가 있으면 다른 포트로 자동 변경하지 않는다.

테스트 도구가 필요하면 `npm ci --include=dev` 후 `npm test`, `npm run test:rules`를 실행한다. 자세한 내용은 [README](../README.md)를 따른다.

## 외부 연결과 데이터

- Firebase 프로젝트: `flashcars-294bc`.
- Firestore 기본 데이터베이스: 서울 `asia-northeast3`.
- 초기 용어 239개 등록 완료. 기존 문서가 있으면 덮어쓰지 않는 조건으로 원자적 등록했다.
- Google이 확인한 관리자 이메일만 쓰기 허용. 일반 방문자는 로그인 없이 공개 용어를 읽는다.
- localhost와 사이트 호스트를 Firebase 인증 허용 도메인에 추가했다.
- 원본 CSV와 검토 JSON은 `data`에 보존하며 공개 앱 배포에는 포함하지 않았다. 학습용 정리 데이터는 `public/terms.json`이다.
- Firebase 웹 앱 공개 설정만 소스에 포함하며 서비스 계정 비공개 키·OAuth 토큰은 저장하지 않는다.
- Analytics 추적은 연결하지 않았다. Google Cloud 액세스 토큰은 초기 설정 시 stdin과 메모리로만 전달했다.
- Firebase의 공개 읽기 규칙과 GitHub Pages의 정적 사이트 공개 범위는 서로 다른 계층이다. 공개 카드 조회와 회원 기록 쓰기 권한은 `firestore.rules`를 기준으로 확인한다.
